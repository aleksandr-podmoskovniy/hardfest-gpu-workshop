# HardFest workshop

Русскоязычный воспроизводимый мастер-класс, не оператор кластера.

- Официальное название доклада: «Инференс без простоя GPU: чиним LLM-сервис руками и делим карту на живом кластере». Сохранять целиком в H1 README.md и RTX5060.md; оборудование — отдельный подзаголовок, не новое название. Автор: Александр Подмосковный, Флант / Deckhouse Platform.
- README.md — самостоятельный сценарий H100, RTX5060.md — самостоятельный сценарий RTX. Сверху QR на репозиторий. Не заменять их обзором и не дробить на лабораторные: действия и нужные команды рядом с объяснением. WORKSHOP.md — только ссылка для совместимости. Подготовка и справка администратора — docs/.
- Образец подачи — авторские мастер-классы OpenStack Demo-cloud и IT Elements: цель, архитектура, последовательные команды, проверка результата. Не превращать материал в сценарий выступления.
- Основные страницы — связное объяснение с воспроизводимыми командами: работающая модель → нагрузка и симптомы → причина → изменение → сравнение результата. Живые переходы вроде «разберём причину» допустимы; списки команд аудитории, постановочные действия администратора и договорённости с соседями — нет. Не публиковать реплики докладчика, частную памятку и поминутный режиссёрский план.
- Порядок обязателен: Base под нагрузкой и три группы ограничений → память, расчёт KV и B Cache → prefill/decode и B Tune → device plugin, DRA, MIG/MPS и небольшие сервисы A30 → автоматизация уже разобранной ручной работы через AI Inference → вывод об оптимизации имеющихся ресурсов → учёт в gateway → большая модель TP2. InferenceService впервые объясняется в разделе автоматизации, не как неизвестный термин в описании Base. Название реального дашборда AI Inference / Service performance не является введением сервиса. Подробный разбор prefill/decode следует за памятью. Не предлагать автоматически «нарезать GPU силами DRA»: возможности зависят от драйвера и оборудования.
- С закрытыми details должно оставаться законченное объяснение; с открытыми — воспроизводимые действия и полный расчёт. Термин вводится вместе с проблемой, которую он решает. Исходное условие — подготовленная A. Описание запуска и ожидаемый эффект не являются измерением; «очередь исчезла», «быстрее в N раз» требуют сопоставимых результатов. Не заменять сокращение повторов переносом всей прежней страницы в раскрытия.
- Писать обычным техническим русским: короткие абзацы, смысловые подзаголовки, списки действий, таблицы сравнений. При первом упоминании объяснять термин простыми словами. Подробные разборы допустимы в details, но обязательные условия и предупреждения должны быть видны перед командой. Без рекламных вступлений, декоративных подписей с «·», эмодзи и повторяющихся жирных меток «Задача / Вывод / Ожидаемый результат».
- Не превращать планы, server-side dry-run и проверку файлов моделей в доказательство CUDA/inference.
- Производительность публиковать только с сырыми результатами, конфигурацией и одинаковой нагрузкой A/B.
- Основной маршрут участника: Helm-чарт и values в GitLab k8s-config → commit/push → Argo CD в управляющем кластере → GPU-кластер. Без Kustomize, Python-обвязки и прямого scale/helm upgrade поверх GitOps. Параметры vLLM задаются в values; чарт формирует ConfigMap и checksum Pod автоматически. Один профиль и затем привязки площадки; варианты B не накладывать друг на друга.
- Публичные файлы не содержат внутренних адресов, kubeconfig, credentials, приватного registry или персональных путей. Привязка площадки хранится в частной GitOps-репе; .local — только приватные операторские артефакты. Секреты не коммитить ни в публичный, ни в частный Git в открытом виде.
- Все workload-манифесты по умолчанию replicas: 0. Не создавать Argo autosync.
- Не создавать вручную DeviceClass: использовать классы установленного GPUClass/GPUPool-контроллера. Не выдумывать новую CRD-схему по названию продукта.
- Не менять MIG mode, драйверы, VFIO, cordon, маршруты, политики безопасности и чужие workloads без отдельного согласования.
- Не удалять Namespace, PVC, модели, GPUClass/GPUPool при cleanup.
- Проверки: python3 -m unittest discover -s tests -v; python3 scripts/check_public.py.
- Git commits: git commit -S -s. Не менять global Git/GPG, не экспортировать закрытые ключи.
- Публикация в GitHub и изменения кластера — отдельные действия, не следствие генерации Markdown.
