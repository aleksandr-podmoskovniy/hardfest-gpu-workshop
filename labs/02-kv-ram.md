# KV-кэш в RAM

Сравним два способа повторно обработать большой документ после его вытеснения из GPU: выполнить prefill заново или вернуть сохранённый KV-кэш из RAM.

Нужны работающий B, файл `.local/long.jsonl` из 32 документов и достаточная свободная память узла. Проверьте также лимит памяти контейнера. Подготовка описана в [настройке площадки](../docs/SETUP.md).

## Профиль

[gemma-b-cache.json](../manifests/profiles/gemma-b-cache.json) отличается от tuned-профиля настройкой выгрузки KV:

```json
{"kv-transfer-config":{"kv_connector":"OffloadingConnector","kv_role":"kv_both","kv_connector_extra_config":{"cpu_bytes_to_use":68719476736}}}
```

64 GiB — начальный бюджет эксперимента. Он общий для рабочих процессов и должен укладываться в их лимиты памяти. Это значение не определяется моделью GPU автоматически. Веса остаются на GPU. [Выгрузка KV в vLLM](https://docs.vllm.ai/en/v0.30.0/features/kv_offloading_usage/).

## Последовательность действий

1. Перезапустите B с tuned-профилем, переподключите port-forward.
2. Выполните X → остальные 31 документ → X. Сохраните результат в `results/raw/cache-off`.
3. Перезапустите B с cache-профилем, переподключите port-forward.
4. Повторите ту же последовательность в `results/raw/cache-on`.
5. Сопоставьте оба `x-return`: время prefill, ожидание в очереди, TTFT, запись и чтение KV в RAM, состояние GPU-кэша.

[Полные команды для обеих серий](../README.md#ram). Каждая серия начинается с нового процесса движка; для прогрева используется отдельный префикс. Сравнивайте повтор X отдельно от остальных документов нагрузки.

## Проверка

```bash
curl --fail --max-time 15 http://127.0.0.1:18002/metrics
```

Найдите в метриках работающего сервиса счётчики записи и чтения KV-коннектора. Нужно подтвердить три события: сохранение X в RAM, вытеснение из GPU и обратную загрузку. Обработка 31 другого документа сама по себе не гарантирует вытеснение; если X остался на GPU, этот прогон не измеряет пользу RAM.

При попадании в RAM-кэш префикс возвращается на GPU. Время и объём повторного prefill можно сравнить с контрольной серией. Одна запись о включённом коннекторе в конфигурации попадание не подтверждает.

## Если результат не получен

- Не хватило RAM: проверьте бюджет коннектора, лимит cgroup и потребление остальных процессов.
- Коннектор не поддержал модель: сохраните ошибку запуска и вернитесь к совместимой конфигурации.
- Префикс остался на GPU: увеличьте разнообразие нагрузки в пределах доступных ресурсов и повторно проверьте вытеснение.
- Нет нужных счётчиков или трассировки: попадание в RAM-кэш пока не подтверждено.
- Время выросло: измерьте затраты на передачу и конкуренцию за память. Выгрузка KV не обязана ускорять холодный запрос.

## Завершение

```bash
python3 scripts/hf.py stop b-cache --ack
```

Это останавливает только B и сохраняет модели/PVC. Следующий профиль применяется к тому же Deployment.
