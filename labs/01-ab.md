# 1. Gemma A/B на двух H100

Вход: [подготовленная площадка](../docs/SETUP.md), обе H100 свободны, модели локальны. Выход: два API и сохранённые одинаковые серии.

## Поднять

```bash
python3 scripts/hf.py apply a --ack
python3 scripts/hf.py apply b-tuned --ack
python3 scripts/hf.py start a --ack
python3 scripts/hf.py start b-tuned --ack
python3 scripts/hf.py get resourceclaims
python3 scripts/hf.py logs a
python3 scripts/hf.py logs b-tuned
```

DRA должен дать разные **физические** устройства. Сверить device IDs в allocation и CUDA-visible UUID. Снимок `nvidia-smi` с хоста ещё не доказывает, какую GPU видит контейнер.

В логах записать: effective config, формат KV, capacity, backend, compilation/capture, доступную память. Пройти smoke на обеих репликах. 200 `/health` — необходимая, но недостаточная проверка: нужен сгенерированный ответ.

## Сравнить

```bash
python3 scripts/hf.py port-forward a 18001
# В другом терминале:
python3 scripts/hf.py port-forward b-tuned 18002
```

В третьем терминале выполнять серии из [методики](../docs/MEASUREMENTS.md). Если CPU/память ноды общие, сначала A, затем B, потом поменять порядок, а не давать две нагрузки одновременно и считать их независимыми.

## Если 256K не поместилось

Сохранить ошибку startup и бюджет памяти. Подобрать общее окно в `.local/site.json: context_tokens`, явно остановить оба Deployment, повторить apply/start. Не включать скрыто CPU weight offload. Таблица скорости использует одинаковое окно; таблица вместимости отдельно показывает границу каждого профиля.

## Проверить результат

- Ошибки и OOM не скрыты.
- Одинаковые revisions, prompt SHA и настройки sampling.
- Длина входа подтверждена server usage.
- Префиксы холодной серии действительно разные, нет готового ответа из gateway cache.
- Если baseline уже использовал graphs/chunking/prefix cache, это записано как совпадение, а не «оптимизация выключена».

Остановка: `python3 scripts/hf.py stop a --ack` и `… stop b-tuned --ack`. Это сохраняет общие PVC.
