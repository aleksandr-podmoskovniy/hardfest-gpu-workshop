# Повтор ручного запуска через Deckhouse

Перед применением нужен экспорт манифестов, проверенный на установленной версии модуля. Такого универсального манифеста в репозитории пока нет. YAML от другой версии ai-inference может содержать несовместимые поля.

## Предварительные требования

Запишите версии Console, ai-inference, ai-models, GPU-модуля и образ движка. Проверьте схемы через `kubectl api-resources` и `kubectl explain`, явно указав kubeconfig и context. Интерфейс Console из main может не соответствовать CRD установленного релиза. Статус Ready в интерфейсе не заменяет проверку API.

В namespace `hardfest-demo` создайте через мастер Console сервис `hf-platform-gemma`:

1. Выберите источник ai-models, модель и точную версию из `models.lock.json`.
2. Выберите профиль существующего GPUClass/GPUPool, выделяющий одну H100.
3. Задайте то же окно, что у A/B. Выгрузку весов в RAM не включайте.
4. Начните со стратегии Latency для интерактивного чата. Throughput меняет приоритеты планирования, но сам по себе не означает включение выгрузки KV.
5. Перед подтверждением проверьте предложенный план и причины размещения.

Сохраните `spec` и фактические аргументы запуска в `.local/platform/`, без Secret, `status` и `managedFields`. Проверьте манифест через server-side dry-run на той же версии API. После проверки обезличенный пример можно добавить в `manifests/platform/` с указанием версии CRD. Не редактируйте Deployment, которым управляет контроллер: при следующем согласовании состояния он перезапишет изменения.

## Создание сервиса

```bash
python3 scripts/hf.py stop a --ack
python3 scripts/hf.py get resourceclaims
```

Дождитесь освобождения карты A и создайте сервис из мастера. Проверьте всю цепочку: Model → InferenceService → план → ResourceClaim → Pod → API.

Сопоставьте ручной и платформенный запуск:

| Ручная настройка | Что проверить у платформы |
| --- | --- |
| Версия модели и токенизатор | Те же файлы, а не только похожее имя |
| Контекст и точность | Фактические аргументы, ёмкость кэша и конфигурация движка |
| FP8 KV, chunked prefill, CUDA graphs | Настройки плана применены движком |
| Выгрузка KV в RAM | Нужный коннектор и бюджет памяти, если они поддерживаются |
| Спекулятивное декодирование | Поддержка в установленной CRD и движке |
| GPU | ResourceClaim получил нужное физическое устройство |

Подайте тот же набор запросов напрямую в API сервиса. Если движок или доступные функции отличаются, укажите это в сравнении: одинаковых условий в таком случае нет.

## Освобождение H100 для TP2

В Console удалите только `hf-platform-gemma`, созданный в этой работе. Убедитесь, что его Pod и заявки исчезли, а модели и PVC остались. Пока сервис занимает карту A, запустить Qwen на обеих H100 нельзя. Скрипт `hf.py` платформенный сервис не удаляет.
