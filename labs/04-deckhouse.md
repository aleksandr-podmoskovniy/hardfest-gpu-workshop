# От ручного профиля к сервису платформы

В этой работе переносим ручную конфигурацию в рецепт AI Inference.
Рецепт объединяет runtime, параметры движка и бюджет ресурсов; платформа
формирует план размещения и запускает сервис.

## Рецепты мастер-класса

| Рецепт | Настройки эксперимента |
| --- | --- |
| Gemma 64K | Один H100, FP8 KV, prefix cache, chunked prefill, CUDA graphs; те же настройки, что у ручного B |
| Gemma 128K | Расширенное окно при сохранении оптимизаций Gemma 64K |
| Gemma 128K с KV в RAM | KV-offload и согласованные бюджеты CPU RAM и shared memory |
| Gemma с assistant | Основная модель и черновик; отдельное сравнение принятия токенов и скорости без RAM-offload |
| Qwen TP2 с MTP | Две H100, встроенный MTP, prefix cache, chunked prefill, CUDA graphs и KV-offload с заданным бюджетом |

Подготовка стенда включает весь этот набор рецептов. Состояние их сборки и
результаты прогонов ведутся отдельно в [техническом статусе](../docs/STATUS.md).

Для первого сравнения выберите Gemma 64K и стратегию Throughput. Исходные веса,
API-модель, контекст и параметры генерации совпадают с ручным B.

## Последовательность

1. Откройте рецепт Gemma 64K и сопоставьте его параметры с ручным B.
2. Остановите Application A изменением replicaCount в values, push/sync.
3. Создайте в Console сервис `hf-platform-gemma` с той же моделью из ai-models,
   рецептом Gemma 64K и стратегией Throughput.
4. Проверьте итоговый план: образ, GPU-класс, max-model-len, KV dtype, chunking,
   prefix cache и CUDA graphs. У этого рецепта веса и KV остаются на GPU;
   перенос KV в RAM относится к следующему отдельному эксперименту.
5. Дождитесь запуска и выполните тот же API-запрос, затем тот же benchmark.
6. Добавьте новый отдельный маршрут Bifrost и проверьте его в прежнем Open WebUI.

Проверьте ресурсы непосредственно в целевом кластере:

```bash
kubectl --context "$GPU_CONTEXT" api-resources | grep -i inference
kubectl --context "$GPU_CONTEXT" -n hardfest-demo get pods,resourceclaims
```

Не выдумывайте YAML InferenceService под другую версию API. Для GitOps сохраните
манифест по **установленной** схеме, исключив status, managedFields и учётные данные,
проверьте dry-run и назначьте ему одного владельца Application.
Ручное Application A не должно управлять дочерним StatefulSet платформенного сервиса.

Сопоставляйте реальные параметры процесса и измерения, не только Ready в Console.
В расширенных рецептах дополнительно проверьте объём CPU KV, конфигурацию
Gemma assistant или Qwen MTP. Для черновой генерации фиксируйте долю принятых
токенов, для offload — запись и возврат KV из RAM.

После опытов с Gemma и A30 переходите к [Qwen TP2 с MTP](06-tp2.md):
освободите обе H100 и создайте один сервис с двумя GPU. Это следующий этап
программы, а не две дополнительные реплики Gemma.
