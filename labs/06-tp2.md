# 6. Большая Qwen на двух H100

Финал по готовности, не обязательный этап пяти минут. Lock содержит `nvidia/Qwen3.8-Flash-Next-NVFP4`. Исторически проверены файлы, но не успешная работа на этих H100. Сначала закрыть hardware gates из [STATUS](../docs/STATUS.md).

Safetensors занимают 132680249378 байт (~123,57 GiB). Это размер файлов, а не ожидаемый объём HBM каждого rank. Модель имеет смешанное представление и дополнительные тензоры; деление размера на два недостаточно для memory plan.

Профиль [qwen-tp2.json](../manifests/profiles/qwen-tp2.json): TP2, modelopt/Marlin, без engram CPU weight offload, chunking/prefix-cache/graphs. Не добавляем MTP, FP8 KV и CPU-tier одновременно при первом запуске: совместимость hybrid state/cache и выбранного MoE backend проверяется отдельно.

## Hardware gate

- Обе H100 свободны от A/B и сервиса Deckhouse, не VFIO; node Ready, не cordoned.
- CUDA видит обе карты внутри **правильного** DRA allocation.
- Топология действительно содержит нужный NVLink, а NCCL collective проходит без ошибок.
- Runtime поддерживает архитектуру и quantization kernels, фактическая VRAM/RAM достаточна.
- Между стартами сохранены логи и точный profile hash.

В конфигурации нет разрешения автоматически освободить чужую нагрузку. Пока gate не закрыт, Deployment остаётся replicas=0.

```bash
python3 scripts/hf.py apply tp2 --ack
python3 scripts/hf.py start tp2 --ack
python3 scripts/hf.py logs tp2
python3 scripts/hf.py port-forward tp2 18004
```

```bash
python3 scripts/bench.py --url http://127.0.0.1:18004 --model qwen3.8-flash-next \
  --dataset examples/smoke.jsonl --requests 2 --concurrency 1
```

Затем длинный dataset готовится **заново с tokenizer Qwen**, а не с количеством токенов Gemma.

## На сколько сессий рассчитывать

До конференции пройти 1 → 2 → 4 → 8 → 16 → 32 → 50 concurrent requests. Для каждой точки сохранить длины, completion rate, errors, queue, TTFT, ITL, output throughput и preemptions. Число запросов должно превышать concurrency, чтобы измерять устойчивую работу, а не один burst. Записывать и client-side pacing.

50 пользователей с короткими паузами и 50 одновременных 256K запросов — принципиально разные нагрузки. Допустимая точка выбирается по согласованному SLA, а не по тому, что HTTP вернул 200. `max-num-seqs: 16` не означает «максимум 16 пользователей»: другие могут ожидать; этот предел тоже параметр эксперимента.

## Почему не PP2 автоматически

PP требует поддержки конкретной архитектуры и runtime. TP/PP сравнивать на одной модели, precision, окне и workload. Для TP существенны collective communications; для PP — разделение стадий и заполнение pipeline. Только после проверки `SupportsPP` и реального запуска добавлять отдельный PP2-профиль. Количество GPU само по себе совместимость не доказывает.

## После первого успешного запуска

Отдельные кандидаты: MTP → память/acceptance/speed; CPU KV-tier → доказанный reload и влияние на hybrid state; FP8 KV → совместимость/качество/ёмкость. Переносить оптимизацию в основной профиль только после воспроизводимого сравнения.
