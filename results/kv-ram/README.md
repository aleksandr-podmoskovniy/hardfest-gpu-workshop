# Возврат длинного префикса из RAM

Gemma на одной H100 восстановила KV из RAM после вытеснения из GPU.
Это проверка механизма на одном повторе документа, не p95, не число
одновременно обслуживаемых пользователей и не завершённое сравнение cache-off/cache-on.

## Что запущено

vLLM 0.30.0, Gemma 4 31B, окно 131 072, BF16-веса, FP8 KV,
TRITON_ATTN, prefix cache, CUDA graphs и prefill порциями по 4096.
GPU KV-пул — 26,49 GiB по логу запуска, CPU KV — 32 GiB.
Веса не выгружаются. На VM с 128 GiB вторая реплика остановлена.
Лимит контейнера — 80 GiB, shared memory — 40 GiB.

Один клиент отправлял синтетические документы: по 65 536 токенов входа
и ровно 128 выхода, temperature 0. Короткий фиксированный ответ выбран,
чтобы проверить кэш, а не скорость длинной генерации.
Запросы шли прямо в API vLLM через port-forward, без Bifrost и Open WebUI.

## Наблюдение

| Один и тот же документ | Первый запрос | Повтор после вытеснения |
| --- | ---: | ---: |
| Время до первого токена | 57,29 с | 1,47 с |
| Весь запрос | 62,22 с | 6,41 с |
| Вход / выход | 65 536 / 128 | 65 536 / 128 |

Оба запроса выполнены **с включённым offload**. Первый ещё не имел
сохранённого KV, повтор использовал его. Это не сравнение «без оптимизаций /
с оптимизациями». Первичный запрос также мог включать расходы первого
выполнения этого размера; из одной пары нельзя выводить стабильный коэффициент ускорения.

Для повтора отдельно получены: очередь — 0,246 с, prefill — 0,220 с,
измеренная коннектором передача CPU → GPU — 0,180 с.
Это разные интервалы движка, их нельзя механически складывать и называть
полным клиентским TTFT.

## Почему это RAM, а не обычный GPU-cache hit

Изменения счётчиков за повтор:

| Счётчик | Приращение |
| --- | ---: |
| CPU → GPU, байты | 3 102 474 240 — около 2,89 GiB |
| Внешний prefix cache, токены | 65 504 |
| Локальный GPU prefix cache, токены | 0 |
| Вычисленные заново токены входа | 32 |

Все 65 536 токенов входа учтены: 65 504 восстановлены, 32 вычислены.
Чтение из RAM подтверждено одновременно переносом байтов и источником токенов.

## Как дошли до вытеснения

Фактическая последовательность документов, индексы с нуля:

```text
0 → 1 → 2 → 3 → 4 → 5 → 6 → 0 → 7 → 8 → 9 → 1
```

Первый повтор документа 0 после семи разных документов оказался **GPU-hit**:
1,24 с до первого токена, но CPU → GPU = 0. Поэтому его не записали
в результат offload. После трёх дополнительных документов повторили
более старый документ 1 — и получили подтверждённое чтение из RAM.
Все 12 длинных запросов завершились без ошибок.

В новом эксперименте начинайте с десяти разных документов, но проверяйте
счётчики: нужное число зависит от модели, типа KV и фактического GPU-пула.
Контрольная серия без CPU KV должна иметь тот же набор и порядок.
Она пока не завершена.
