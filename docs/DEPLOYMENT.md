# Порядок развёртывания

Мастер-класс использует две H100 для LLM и отдельную A30 для небольших моделей.
Gemma и Qwen запускаются последовательно: финальному Qwen нужны обе H100.
Open WebUI, Bifrost, базы знаний и поисковый индекс сохраняются при смене LLM.

## До начала практики

1. Подготовьте ноды, DRA, классы, namespace и PVC по [SETUP](SETUP.md).
2. Загрузите закреплённые веса и образы; подготовьте весь набор
   [рецептов AI Inference](../labs/04-deckhouse.md#рецепты-мастер-класса), включая Qwen TP2 с MTP.
3. Перенесите [чарт и values](../charts/vllm-runtime/README.md) в GitLab.
4. Зарегистрируйте Application в управляющем кластере, примените коммит
   с нулём реплик и проверьте состав ресурсов.
5. Подготовьте точные маршруты Bifrost, ACL моделей, личные VK участников
   и отдельный административный путь к MCP по [руководству доступа](CHAT_AND_ACCESS.md).
6. Проверьте GPU и NCCL, доступность API, метрик и репозиториев. Прогон Qwen
   до занятия должен подтвердить запуск именно с выбранным рецептом;
   скачанные веса и успешный рендер манифеста этого не доказывают.

Все команды commit/push/sync — в [GITOPS](GITOPS.md). Autosync для учебных
Application не включён. Ветка GitLab — источник состояния; прямой
`kubectl scale` поверх GitOps не используется для переключения этапов.

## Полный маршрут

| Этап | H100 | A30 | Проверка перехода |
| --- | --- | --- | --- |
| Gemma A/B | Два независимых запуска по одной GPU, одинаковое окно 64K | Поисковые сервисы | Две заявки, два точных маршрута Bifrost, ответ обеих моделей |
| AI Inference | A остановлена; платформенная Gemma 64K рядом с B | Без изменений | Рецепт, план, одна GPU, те же параметры и запросы, что у B |
| Контекст и RAM | Платформенная Gemma остановлена; B сначала 128K без offload, затем с ним | Без изменений | Освобождена заявка платформенной Gemma; возврат KV подтверждён счётчиками |
| Динамический MIG/MPS | Конфигурация B не меняется | Новые разделы и MPS-клиенты по DRA-заявкам | UUID устройств, квоты, совместное размещение и освобождение заявок |
| Qwen TP2 с MTP | A/B остановлены; один платформенный сервис на двух GPU | Поиск продолжает работать | Две GPU одной ноды, TP=2, MTP, API и чат через прежний шлюз |

Основные команды следуют этому порядку в [README](../README.md). В пределах
занятия для Qwen обязательны запуск, короткий ответ API, работа через Open WebUI,
проверка MTP и административного MCP. Полная нагрузочная серия до 50 клиентов
и парное измерение MTP on/off выполняются отдельно по [упражнению TP2](../labs/06-tp2.md).
Gemma assistant — самостоятельный дополнительный эксперимент, не замена финалу Qwen.

Если старт Qwen требует заметного ожидания, после опыта с RAM остановите B и
начните загрузку Qwen, а затем выполните упражнение MIG/MPS на независимой A30.
После готовности Qwen вернитесь к проверке API и чата. Не переносите на время
занятия первичное скачивание весов, сборку образа или диагностику оборудования.

## Проверка после изменения

Для ручного B:

```bash
kubectl --context "$ARGO_CONTEXT" -n "$ARGO_NAMESPACE" get applications hardfest-gemma-a hardfest-gemma-b
kubectl --context "$GPU_CONTEXT" -n hardfest-demo get pods,resourceclaims
kubectl --context "$GPU_CONTEXT" -n hardfest-demo rollout status deployment/hf-gemma-b --timeout=15m
kubectl --context "$GPU_CONTEXT" -n hardfest-demo logs deployment/hf-gemma-b --tail=100
```

Сверьте revision завершённой операции Argo с SHA отправленного коммита.
Для платформенного сервиса найдите его дочерние ресурсы в Console: не предполагается,
что контроллер именует StatefulSet точно так же, как InferenceService.
Сопоставьте образ, параметры процесса и выделенные GPU с рецептом. Healthy
не доказывает правильную модель; нужен ответ API и запрос через Open WebUI.

## Откат и остановка

Отмените свой коммит через `git revert`, отправьте изменения и синхронизируйте
ту же Application. При изменении DRA чарт создаёт новое имя ResourceClaimTemplate
и обновляет ссылку Pod; не используйте force для изменения неизменяемой заявки.

Платформенный сервис удаляется через его InferenceService и владельца конфигурации,
не через дочерний workload. В GitOps после удаления декларации нужен адресный
Prune только этого InferenceService: основной sync с `prune: false` его сохранит.
Проверьте список удаления в Argo, исключив Namespace, PVC и соседние сервисы.
Перед восстановлением Gemma после Qwen дождитесь
освобождения обеих GPU. Учитывайте время повторной загрузки модели.

Перед остановкой согласуйте завершение запросов участников и выгрузите результаты
из временных каталогов Pod. Namespace, PVC, веса, GPUClass/GPUPool, Open WebUI,
Bifrost, базы знаний и чужие заявки не входят в очистку учебной GPU-нагрузки.
