# Если что-то не работает

| Симптом | Что проверить | Что важно учесть |
| --- | --- | --- |
| Таймаут или ошибка TLS при доступе к API | VPN, маршрут, `expected_server`, прокси для API и OIDC issuer, срок SSO-сессии | При прямом VPN-маршруте проверьте обход прокси только для этих адресов; не меняйте глобальный kubeconfig и TLS остальных кластеров |
| Pod в Pending | События, `nodeSelector`, taints, созданный контроллером DeviceClass и свободные GPU | Причину `cordon` выясняйте у администратора; чужие ResourceClaim не удаляйте |
| ImagePullBackOff | Digest образа и Secret для доступа к реестру в нужном namespace | Для проверки достаточно имени и ссылок на Secret, его содержимое выводить не нужно |
| Файлы модели не найдены | PVC, `subPath`, digest и индекс файлов | Сначала найдите уже доставленные файлы; повторное скачивание может занять весь том |
| CUDA недоступна | UUID выделенного устройства, привязку драйвера, доступ к CUDA внутри Pod | Наличие GPU в списке устройств ещё не означает, что контейнер может её использовать |
| OOM при запуске | Память весов, буферов, графов и KV; длину контекста | Выгрузка весов в RAM меняет условия A/B и должна учитываться как отдельная конфигурация |
| Не хватает RAM при выгрузке KV | Лимит контейнера, закреплённую память, потребление соседних Pod | 64 GiB кэша — только часть памяти процесса |
| OffloadingConnector не помещается в `/dev/shm` | Размер tmpfs внутри Pod и `cpu_bytes_to_use` | Для 64 GiB KV предусмотрено 72 GiB shared memory; это часть лимита контейнера, не дополнительная память |
| `start` сообщает об устаревших настройках памяти | Requests, limits и том `/dev/shm` в Deployment | Остановите профиль и повторите `apply`; изменения генератора сами не меняют ресурсы кластера |
| A и B показывают одинаковую скорость | Фактические настройки, нагрузку и состояние кэша | Часть оптимизаций может уже работать по умолчанию; одинаковый результат тоже полезен |
| Большой TTFT | Время очереди, prefill, передачи и вытеснения запросов | Разность p95 очереди и p95 TTFT не даёт времени вычисления |
| Нет попаданий в кэш RAM | Сохранение и загрузку блоков после вытеснения из GPU | Быстрый повтор мог обслужить префиксный кэш GPU |
| С черновой моделью медленнее | Долю принятых токенов, время предложения и проверки, размер батча | Число черновых токенов подбирается по итоговой скорости, а не только по доле принятия |
| MPS-клиенты получили разные разделы | Выделенные DRA-устройства и UUID MIG | Одинаковый DeviceClass сам по себе не гарантирует общий MIG-раздел |
| После изменения MIG пропали метрики DCGM | Соответствие метрик новой геометрии, метки устройств, обработку их появления | Отсутствие данных не означает нулевую загрузку |
| После остановки остался MIG-раздел | Владельцев Pod и ResourceClaim, настройки сохранения разделов и работу контроллера | Не удаляйте finalizers и не сбрасывайте всю GPU вручную |

```bash
python3 scripts/hf.py get events
python3 scripts/hf.py get pods
python3 scripts/hf.py get resourceclaims
python3 scripts/hf.py logs b-tuned
```

`apply` не меняет профиль работающего Deployment: сначала выполните `stop`. После смены профиля заново запустите `port-forward`.

Если изменяется неизменяемая часть DRA-заявки, скрипт создаёт ResourceClaimTemplate с новым хешем в имени. Старые шаблоны сами по себе GPU не занимают. Удалять их можно после проверки, что ни один Pod их больше не использует.
