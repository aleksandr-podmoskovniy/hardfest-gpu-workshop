# Проверка окружения и результатов

## Перед запуском

- [ ] С владельцем стенда согласованы время работ, используемые GPU и порядок восстановления исходной нагрузки.
- [ ] Ноды Ready, нет неизвестного cordon, обе H100 доступны CUDA через DRA.
- [ ] Записаны модели GPU и объём VRAM, версии драйвера, модулей, CRD и vLLM, топология соединений и результат проверки NCCL.
- [ ] Селекторы GPUClass/GPUPool выбирают только нужные карты; DeviceClass созданы контроллером.
- [ ] Все PVC в состоянии Bound, пути и ревизии моделей проверены, места и квот хватает.
- [ ] Образ vLLM доступен на нодах, доступ к реестру настроен.
- [ ] VPN/SSO и kubeconfig работают; секреты не выводятся в логи и скриншоты.
- [ ] `preflight` показывает ожидаемые адрес API и контекст.
- [ ] Выбраны конфигурации для запуска; чужие сервисы не затрагиваются.

## Для воспроизводимых измерений

- [ ] Измерены время загрузки и компиляции; они отделены от времени запросов.
- [ ] Для A/B совпадают контекст, ревизии модели и токенизатора, SHA256 набора запросов, параметры генерации и формат весов.
- [ ] ResourceClaim получили разные физические H100; конкурирующей нагрузки нет.
- [ ] API отвечает на короткие запросы, ответы проверены.
- [ ] Серии с холодным входом, повтором и длинной генерацией выполнены минимум три раза; исходные результаты сохранены.
- [ ] Перед каждой серией зафиксировано состояние кэша; повтор не назван холодным запросом.
- [ ] Среднее время очереди и prefill отделено от TTFT p95.
- [ ] Возврат KV из RAM подтверждён после вытеснения из GPU; если нет, это отмечено в отчёте.
- [ ] Для черновой модели проверены качество, доля принятых токенов и итоговая скорость.
- [ ] Для сервиса платформы сверены план, фактические параметры запуска, ResourceClaim и ответ API.
- [ ] Для MPS проверены общий MIG-раздел, квоты, ответы эмбеддера и реранкера, метрики потребления.
- [ ] Для TP2 отдельно проверены совместимость модели с движком, соединение карт и доступная память.

Загрузка модели и компиляция могут занять больше времени, чем ожидание в скрипте. Если команда завершилась по таймауту, Pod остаётся в кластере. Проверьте его состояние и логи по [инструкции диагностики](TROUBLESHOOTING.md).

## После упражнений

- [ ] Созданные Deployment `hf-*` остановлены через `stop <stage> --ack`.
- [ ] Созданный `hf-platform-gemma` удалён отдельно через Console.
- [ ] Pod завершены, ResourceClaim освобождены; проверены MIG-разделы и доступные ресурсы.
- [ ] Namespace, PVC, модели и GPUClass/GPUPool сохранены.
- [ ] При необходимости исходная нагрузка восстановлена по согласованному плану.
- [ ] Отчёт заполнен; перед публикацией удалены секреты и приватные данные.
