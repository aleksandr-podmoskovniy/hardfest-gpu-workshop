# Изменения руководства и исходников

Этот файл — для авторов проекта. Для прохождения мастер-класса достаточно
[README](README.md), Git, Helm, kubectl и curl; запускать Python-скрипты не нужно.

## Куда вносить правку

| Что меняется | Файлы | Что проверить |
| --- | --- | --- |
| Последовательность занятия | `README.md`, соответствующая `labs/*.md` | Команды идут в порядке выполнения, результат каждого этапа понятен |
| Подготовка инфраструктуры | `docs/SETUP.md`, `docs/GITOPS.md` | Явные контексты, пути и действия в редакторе, без привязки к личному стенду |
| Настройки runtime | `values/`, `charts/vllm-runtime/` | Helm render, schema, ConfigMap checksum, DRA и нулевые реплики |
| Веса моделей | `models.lock.json`, `catalog/models.yaml`, `catalog/a30.yaml` | Одинаковые закреплённые ревизии, доступ и лицензии |
| Иллюстрации | `scripts/build_diagrams.py`, `assets/` | Пересборка и визуальная проверка SVG |
| Результаты замеров | Отчёт и исходные файлы результата | Одинаковая нагрузка A/B, конфигурации и все ошибки серии сохранены |

Текст пишется для того, кто выполняет действия сам. Нужны причина изменения,
точный файл, команда и проверка — не реплики докладчика и не отчёт о нашей работе.
Обязательные условия размещайте **перед** командой, а не в конце длинного абзаца.
Планы и dry-run не описывайте как проверенный инференс.

## Перед проверками

- Нужны Python 3 и Helm 3+ — это зависимости разработки, не рабочего маршрута участника.
- Для отдельного Go-адаптера нужны инструменты из его [инструкции](integrations/webui-access/README.md).
- Тесты запускаются локально и не должны обращаться к GPU или Kubernetes скрытно.
- Не добавляйте реальные адреса площадки, токены, веса и персональные данные.

## 1. Проверить чарт и профили

Из корня публичного репозитория:

```bash
python3 -m pip install -r requirements-dev.txt
for profile in values/*.yaml; do
  helm lint charts/vllm-runtime --strict -f "$profile" || exit 1
done
helm lint charts/model-catalog --strict -f catalog/models.yaml
python3 scripts/check_manifests.py
python3 -m unittest discover -s tests -v
```

Тесты проверяют рендер профилей, checksum и ссылки DRA. Это не доказательство
загрузки модели, отсутствия ECC и производительности на GPU.

## 2. Проверить текст и иллюстрации

```bash
python3 scripts/build_diagrams.py
python3 scripts/check_public.py
python3 scripts/check_docs.py
git diff --check
git diff --stat
```

Откройте изменённые SVG в браузере. Проверьте текст, стрелки и поля при обычном
масштабе чтения README: автоматические проверки этого не заменяют.
Общий холст — 1200×760, отступ — 48, шрифты и палитра едины.
QR `assets/workshop-qr.svg` должен вести на главную страницу этого GitHub-проекта.

Проверьте скриншоты отдельно: в адресной строке и настройках не должно быть
токенов. У чужих документов и изображений должны быть права на распространение.

## 3. Подготовить commit

Добавляйте только файлы своей правки, затем просмотрите staged diff:

```bash
git diff --cached --check
git diff --cached
git commit -S -s -m "Describe one workshop change"
```

`-S` подписывает commit настроенным ключом автора, `-s` добавляет
[DCO sign-off](https://developercertificate.org/). Используйте собственные имя,
email и ключ; не копируйте чужую identity и закрытый ключ в fork.

Публикация в GitHub и развёртывание на стенде — отдельные действия.
Проверка документации не должна автоматически менять работающий кластер.
