# Персональный доступ участников

Статус на 2026-10-01: адаптер развёрнут рядом с Open WebUI, подключение двух
Gemma переведено с общего VK на личные ключи. Одобрено и обслуживается
13 реальных аккаунтов; после удаления двух проверочных ключей осталось
17 отключённых ключей в резерве. Инструкция — в [README.md](README.md).

## Проверено на стенде

- Запросы к обеим Gemma через API Open WebUI с сессией обычного пользователя,
  включая SSE и завершающий chunk usage. В Bifrost указан его личный VK.
- Шесть запросов A/B на трёх репликах шлюза: все успешны, каждый имеет
  личный VK и стоимость по тарифу. Четыре запроса с 33 входными и 2 выходными
  токенами стоили по $0,00037; два с 35 входными и 2 выходными — по $0,00039.
- Два SSE-запроса через WebUI: по 20 входных и 4 выходных токена,
  по $0,00028. Отдельный проверочный пользователь имеет другой VK и свой
  запрос на $0,00028. Общая статистика читается через `/api/logs/stats`;
  поле `stats` списка `/api/logs` не заменяет этот запрос.
- На срезе проверки статистика основного тестируемого аккаунта содержит
  12 успешных запросов, 362 токена и $0,00313. Локальные бюджетные дельты
  трёх реплик составили $0,00135 + $0,00076 + $0,00102 = $0,00313;
  каждая реплика видит две удалённые дельты. Эти 12 запросов включают
  раннюю диагностику до полной синхронизации тарифа, поэтому весь срез
  нельзя использовать для проверки тарифа простой суммой всех токенов.
- Pending-аккаунт получает 403, поддельная подпись — 401. После одобрения
  назначается отдельный ключ; MCP-запрос запрещён. Перевод обратно в pending
  блокирует следующий запрос; сверка отключает VK.
- В первой попытке сразу после выдачи получен 403 от реплики Bifrost,
  ещё не увидевшей активацию. Повтор через 3 секунды прошёл. Это задержка
  распространения конфигурации, не доказательство мгновенной выдачи.
- Повторные сверки сохраняют ID ключа. API обновления не получает полей
  сброса расхода. Исчерпание бюджета и RPM пока не проверялось вживую.
- Конфигурация отдельного System OAuth подключения сохранена без изменения.
  Интерактивный OIDC-вход и выполнение MCP в этом прогоне не проверялись.

Короткие запросы выше проверяют доступ и учёт, а не производительность GPU.
Тестовые аккаунты, их два VK и шесть тарифов удалены; логи оставлены.
Реальные пользователи, история чатов и документы сохранены.

## Обнаруженные ограничения

На проверенном Bifrost `v2.0.38-d8-edition` создание временного VK с сервисным
management-ключом вернуло HTTP 500 **после записи ключа**: сервер не смог
перезагрузить его в память. Ошибка повторилась без бюджета, лимита частоты
и разрешённых провайдеров. Это не означает неисправность существующих VK
или сбой создания из административного интерфейса: создание, чтение,
ротация и удаление через администраторскую сессию проверены успешно.

Сервисный management-ключ ограничен `own_data`. Поэтому отсутствие проверочных
VK в его списке не доказывает их удаления. Административная проверка нашла
и удалила десять временных ключей неудавшихся проверок. Повторять создание
после такого 500 нельзя.
На этом этапе подключение Open WebUI ещё не переключалось. Новый пакет
Bifrost для обхода проблемы не выпускался и не устанавливался.

Дополнительно проверен штатный Access Profile с отдельной сервисной учёткой
и ограничением `own-data`. Профиль создаёт ключ с HTTP 201; список ключей
владельца видит его, но общее API управления VK возвращает 404. После
штатного обновления кэша RBAC ранее созданный ключ становится доступен
тому же management-ключу без расширения прав. Повторная проверка на новом
временном VK воспроизвела расхождение; этот VK удалён через API профиля.
Это отдельная проблема обновления видимости собственных объектов,
а не неисправность существующих токенов. Поэтому развёрнутый адаптер
назначает заранее подготовленные отключённые VK вместо повторения
проблемного POST. Management-ключу не выдавались широкие права.

Другой обнаруженный случай: pricing override сохраняется, но не сразу
попадает в память всех реплик HA Bifrost. Тарифы синхронизированы через
штатное API на каждой реплике, одинаковая цена дополнительно закреплена
за двумя provider key Gemma. Это обеспечивает тариф новым участникам
до распространения их персональных overrides; расход остаётся на личном VK.

При изменении Helm `extraEnvFrom` был ошибочно заменён весь прежний список
Secret. Из-за отсутствия DATABASE_URL WebUI кратковременно стартовал с пустой
SQLite. Исходные ссылки на runtime Secret и PostgreSQL восстановлены;
проверено наличие всех прежних аккаунтов. Основная база не удалялась.

Локальные тесты Go проверяют подпись, актуальную роль, запрет MCP, ограничение
параллельности, резерв, тариф и SSE: 26 проверок, включая подслучаи,
проходят с `go test -race`. Чарт `charts/webui-access` по умолчанию остановлен.

Open WebUI остаётся источником учётных записей и решений администратора.
Внутренний адаптер проверяет подписанный JWT пользователя, повторно проверяет
его роль через API Open WebUI и подставляет личный Virtual Key Bifrost.
API управления Bifrost используется только для ресурсов с собственной меткой.
OIDC-подключение и OAuth/MCP ведущего не переключаются на этот адаптер.

Тариф демонстрационный, без списания денег: вход $10/млн токенов,
выход $20/млн токенов, бюджет $500 на 24 часа. Расход не сбрасывается
при повторном входе, рестарте адаптера или повторном одобрении.

На первом этапе один экземпляр адаптера: это не HA-компонент. Добавлять
реплики без распределённой блокировки выпуска ключей нельзя.
Личные VK никогда не возвращаются браузеру. Подпись пользователя и
межсервисный ключ — разные секреты; неподписанные заголовки не принимаются.

Оставшиеся проверки:

- [x] `pending-user-denied`: pending не получает ответ модели.
- [x] `approved-user-provisioned`: одобрение назначает отдельный VK из резерва.
- [ ] `reconcile-preserves-spend`: проверить сохранность накопленного расхода после рестарта, повторного входа и повторного одобрения.
- [x] `blocked-user-revoked`: новая работа блокируется, VK выключается.
- [x] `forged-identity-denied`: подпись, issuer, срок, sub и актуальная роль проверяются.
- [x] `participant-mcp-denied`: MCP и произвольные provider/model/key не проходят.
- [x] `per-user-usage-recorded`: два пользователя имеют раздельные токены и стоимость.
- [ ] `budget-and-rate-denied`: исчерпание отдельного тестового бюджета/лимита даёт отказ.
- [x] `stream-preserved`: SSE проходит через WebUI с личным VK.
- [ ] `audio-accounting`: голос использует прежний отдельный путь, личный учёт не реализован.
- [ ] `oidc-presenter-preserved`: конфигурация сохранена; нужен новый интерактивный вход и read-only MCP-вызов.

При ошибке API, неполном списке пользователей или неоднозначном VK доступ
закрывается; чужие ключи не исправляются. Проверочные пользователи и ключи
удаляются отдельно от реальных участников. История и документы сохраняются.
