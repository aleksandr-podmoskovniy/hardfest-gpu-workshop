# HardFest: инференс без простоя GPU

**90 минут.** Ведущий держит открытым этот файл, второй терминал с метриками и Console. Подробности раскрываем по ссылкам, не перелистываем десятки манифестов.

Перед показом пройти [репетицию](docs/REHEARSAL.md). Команды ниже реально меняют только явно выбранные demo Deployment; запуск требует `--ack`. Не выполнять этапы с непрошедшими аппаратными gates.

**Режим показа:** Markdown Preview или этот файл на GitHub, терминалы T0 (команды), T1 (A port-forward), T2 (B port-forward). Каждый блок выполняется отдельно; не вставлять весь документ одним shell script. Переходы STOP — реальные условия продолжения, не декоративные предупреждения.

Полная теория презентации раскрыта в [четырёх главах](docs/THEORY.md); [карта переноса всех 52 слайдов](docs/SLIDES_MAP.md) показывает, где находится каждый сюжет. Для быстрого возврата к команде — [CLI-справочник](docs/COMMANDS.md).

## 00–07 · Два одинаковых двигателя, разные условия работы

**Сказать:** «Сегодня не меняем модель ради красивой цифры. Сравним одинаковые веса, запросы и ограничения памяти. Потом превратим ручную конфигурацию в сервис платформы».

Предложить аудитории выбрать учебный документ и задать вопрос в подготовленном чате: «Какие ограничения здесь есть и какие действия предлагаются?». Отметить время первого отклика и первых слов итогового ответа. Не загружать рабочие документы компании. Без готового UI используем прямой API — не изображаем настроенный RAG.

Показать [схему и роли карт](README.md#что-собираем), затем:

```bash
python3 scripts/hf.py preflight
python3 scripts/hf.py get nodes
python3 scripts/hf.py get deviceclasses
```

**Увидеть:** правильный API/context, Ready-ноду, реальные классы GPU. Название H100 в inventory не подтверждает доступ CUDA. Сведения CUDA/NVLink берём из репетиции, не выдаём preflight за GPU-тест.

**Стоп:** NotReady/cordon, чужая нагрузка на выделенных картах, неизвестный владелец DeviceClass. Не чинить сеть/драйвер со сцены.

## 07–18 · Куда уходят память и время

Открыть [теорию](docs/THEORY.md). Нарисовать словами последовательность:

`приём → ожидание scheduler → обработка входа → первый токен → остальные токены`.

Объяснить три отдельных бюджета: HBM под веса/буферы/KV, RAM под offload, контекст одного запроса. `max-model-len` — потолок, не заранее выделенное окно каждой сессии. `max-num-seqs` — предел scheduler, не SLA по количеству пользователей.

**Вопрос залу:** «Если увеличить RAM-кэш, можно ли автоматически увеличить число одновременно активных 256K сессий?» Ответ: нет; сохранённые prefix-блоки не заменяют память активного вычисления.

Разобрать [Q/K/V и пример памяти из презентации](docs/chapters/01-memory.md): 8 KV-heads, 2 KiB на позицию слоя, full + sliding, четыре/восемь независимых историй. Сначала попросить аудиторию посчитать, затем:

```bash
python3 scripts/kv_math.py --sessions 4
python3 scripts/kv_math.py --sessions 8
```

Это арифметика **GPT-OSS**, не вместимость Gemma. Полную выкладку оставляем читателю в главе; на сцене достаточно одного расчёта и объяснения различий.

## 18–30 · Измеряем исходную точку

Профили A/B и сервер заранее прогреты по [лабораторной A/B](labs/01-ab.md). На экране — команды, которыми они были созданы:

```bash
python3 scripts/hf.py render a
python3 scripts/hf.py render b-tuned
# На репетиции, после проверки свободных двух H100:
python3 scripts/hf.py apply a --ack
python3 scripts/hf.py apply b-tuned --ack
python3 scripts/hf.py start a --ack
python3 scripts/hf.py start b-tuned --ack
python3 scripts/hf.py model-info a
python3 scripts/hf.py snapshot a --out .local/runs/ab-a.json
python3 scripts/hf.py snapshot b-tuned --out .local/runs/ab-b.json
```

До сцены генерируем dataset **внутри готового Pod**, с его tokenizer. Файл сохраняется на ноутбуке; путь `/models/gemma` вручную подставлять не нужно. Для повторной репетиции выбрать новое имя файла: существующее не перезаписывается.

```bash
python3 scripts/hf.py dataset a --input-fraction 0.5 --output-tokens 2048 \
  --documents 32 --out .local/long.jsonl
```

В терминале **T1** (команда остаётся работать):

```bash
python3 scripts/hf.py port-forward a 18001
```

В терминале **T2**:

```bash
python3 scripts/hf.py port-forward b-tuned 18002
```

Простейшая проверка транспорта (НЕ замер длинного контекста):

```bash
python3 scripts/bench.py --url http://127.0.0.1:18001 --dataset examples/smoke.jsonl --concurrency 1 --requests 2
python3 scripts/bench.py --url http://127.0.0.1:18002 --dataset examples/smoke.jsonl --concurrency 1 --requests 2
```

Затем выполняем **одинаковый** подготовленный dataset:

```bash
python3 scripts/bench.py --url http://127.0.0.1:18001 --dataset .local/long.jsonl \
  --concurrency 4 --requests 8 --cold --metrics --label a-long --out-dir results/raw/ab
python3 scripts/bench.py --url http://127.0.0.1:18002 --dataset .local/long.jsonl \
  --concurrency 4 --requests 8 --cold --metrics --label b-long --out-dir results/raw/ab
python3 scripts/report.py --directory results/raw/ab
```

На сцене берём число запросов и длину из репетиции, укладывающиеся в слот. Даже эти 8 длинных запросов могут занять больше доступного времени. Полную серию 32 запросов при concurrency 8 выполняем заранее; на сцене подписываем её как запись репетиции. Флаг `--cold` только запрещает повтор строк dataset — он не очищает server cache.

**Показать:** client TTFT, server queue, prefill, output tokens/s, errors. Не называть TTFT только временем работы модели. [Правила измерений](docs/MEASUREMENTS.md).

## 30–41 · Что изменили у B

```bash
python3 scripts/hf.py diff a b-tuned
```

Пояснить FP8 KV, размер шага prefill, capture size. Штатная vLLM уже может включать часть оптимизаций: A не замедляем искусственно. Если фактические настройки A/B совпали — честно показываем это, а не рисуем выигрыш.

Показать [таблицу 8192 → 2048 и три ручки scheduler](docs/chapters/02-scheduler.md). Наше 4096 — начальный кандидат, не единственно правильное значение. Связать изменение с ITL/TTFT и количеством шагов нового документа.

**Важно:** пакет даёт суммарный эффект. Для приписывания ускорения одному флагу нужна отдельная ablation-серия; не утверждаем, что всё ускорил FP8.

## 41–50 · Длинный документ возвращается из RAM

Переход по [лабораторной RAM-cache](labs/02-kv-ram.md).

```bash
python3 scripts/hf.py stop b-tuned --ack
python3 scripts/hf.py apply b-cache --ack
python3 scripts/hf.py start b-cache --ack
```

После перезапуска port-forward переподключить. Сценарий `документ X → другие документы → X`. GPU-кэш X должен реально вытесниться, иначе демонстрируем только GPU prefix hit. На графиках — CPU store/load и объём KV, затем TTFT и очередь отдельно.

Точная последовательность запросов с `--offset` — в [лабораторной](labs/02-kv-ram.md). **До смены B** пройти ту же последовательность на tuned-профиле во время репетиции. Не сравнивать новый cold с уже прогретым старым тестом.

**Резерв:** если в выбранном runtime нет наблюдаемого подтверждения CPU reload, не подписывать график «RAM hit». Показываем конфигурацию и неподтверждённый эксперимент.

## 50–58 · Assistant не волшебный второй мозг

Открыть [speculation](labs/03-speculation.md). Для честного сравнения B tuned против B spec — без одновременного добавления RAM offload.

```bash
python3 scripts/hf.py stop b-cache --ack
python3 scripts/hf.py apply b-spec --ack
python3 scripts/hf.py start b-spec --ack
```

Один длинный ответ, затем несколько параллельных. Измерить acceptance по позициям и output throughput; высокий acceptance сам по себе не равен ускорению. Если хуже — именно это и объяснить. Переходы с длительным рестартом можно заменить подписанными результатами репетиции.

Разобрать [пять предложенных tokens: три приняты, четвёртый отвергнут](docs/chapters/03-speculation.md). Попросить назвать стоимость draft/verify, прежде чем считать speedup. EAGLE3 из старых слайдов — исторический пример; живой профиль использует совместимый Gemma assistant.

## 58–68 · Из ручного запуска в сервис Deckhouse

Следовать [лабораторной Deckhouse](labs/04-deckhouse.md). Освободить A, не B:

```bash
python3 scripts/hf.py stop a --ack
```

В Console создать сервис из ai-models, выбрать согласованный GPU-профиль и стратегию. Показать не только Ready, но и фактический `InferenceServicePlan`, args контейнера, ResourceClaim и живой ответ. Сравнить тот же dataset. Неподдержанные speculation/KV-настройки не маскировать UI-галочкой.

Экспорт точной CRD-формы из установленной версии — обязательный результат репетиции. В учебнике не применяем выдуманный универсальный `InferenceService`.

## 68–81 · GPU меняет геометрию по запросу

Следовать [MIG/MPS](labs/05-mig-mps.md). MIG mode подготовлен заранее; **разделы не преднарезаны**. GPUClass/GPUPool создаёт DeviceClass, драйвер удовлетворяет DRA-заявки.

```bash
python3 scripts/hf.py get deviceclasses
python3 scripts/hf.py apply embed-mig --ack
python3 scripts/hf.py start embed-mig --ack
python3 scripts/hf.py get resourceclaims
```

Показать маленький embedding API, отдельную MPS-партицию с двумя сервисами, их заявки и потребление. Не утверждать, что 25% MPS — гарантированные 25% быстродействия или жёсткая изоляция как у MIG.

Сравнить [MIG / MPS / time-slicing и путь RAG](docs/chapters/04-placement.md). Проверяем каждое API отдельно, затем вместе: правильные результаты, время ответа, errors, пик памяти. В этой части речь уже не о tok/s большой LLM.

Удаляем только demo workload через scale-to-zero, ждём GC claims и освобождения раздела. Рендеры сохраняют PVC; reset всей карты не нужен.

## 81–86 · Две H100 для большой модели

Перед TP2 удалить созданный в предыдущем шаге **конкретный** сервис Deckhouse через Console, дождаться освобождения его claim. Скрипт не трогает ресурсы Deckhouse за пользователя.

```bash
python3 scripts/hf.py stop b-spec --ack
python3 scripts/hf.py apply tp2 --ack
python3 scripts/hf.py start tp2 --ack
```

Это дополнительный финал, только если запуск укладывается в 5 минут. Иначе — сохранённый реальный прогон с конфигурацией и метриками, без имитации live. [TP2 и поиск допустимой нагрузки](labs/06-tp2.md).

## 86–90 · Что забираем с собой

1. Разделяем время очереди, prefill и генерации; не вычитаем p95 друг из друга.
2. Подбираем профиль под модель, железо и нагрузку; «все флаги» не рецепт.
3. Кэш, MIG/MPS и TP решают разные задачи.
4. Платформа должна воспроизводить проверенный запуск и показывать причину размещения.
